# Benchmark: Neve audio lib vs librosa vs torchaudio

Performance and correctness comparison between the Neve language audio
library (`import audio` — see `lib/audio/`) and the Python equivalents
[librosa](https://librosa.org/) and [torchaudio](https://pytorch.org/audio/)
(CPU), following the pattern of the
[NoSavedDATA/Neve_benchmarks](https://github.com/NoSavedDATA/Neve_benchmarks)
repo: one runner per side, internal timers, results table in the README,
reproducible Dockerfile, and an equivalent script in the comparison language.

## Requirements

- Docker
- Linux (tested on Ubuntu 22.04; adapt the pre-docker steps for other setups)

## How to run

From the Neve repository root:

```bash
docker build -f audio_tests/benchmarks/Dockerfile.bench -t neve-audio-bench .
docker run --rm neve-audio-bench
```

The container does everything: builds the audio lib `lib.so` (FFI pattern),
generates the test signals, runs the three benchmarks (librosa, torchaudio
and Neve) `NEVE_AUDIO_BENCH_RUNS` times (default 3), cross-checks correctness
and prints the final tables. Artifacts land in `audio_tests/benchmarks/results/`
(optional volume: `-v $PWD/audio_tests/benchmarks/results:/neve/audio_tests/benchmarks/results`;
`NEVE_AUDIO_BENCH_RESULTS` selects another directory).

## Methodology

- **Signals**: 440 Hz sine + harmonics + noise bursts, 0.9 peak — generated by
  `gen_data.py` (numpy + soundfile, fixed seed). Variants: 1 s / 10 s / 60 s,
  mono 16 kHz (PCM16 and float32) and stereo 22.05 kHz (float32).
- **Common parameters**: `n_fft=1024`, `hop=256`, `win=n_fft`, Hann,
  `center=True` (reflection padding), `n_mels=128`, `fmin=0`, `fmax=sr/2`,
  power=2.0, μ-law with 255 levels, 1.5× stretch.
- **Forced equivalences**: `htk=True, norm=None` on librosa's mel,
  `htk=True, mel_norm=None` on its MFCC and `sr=None` on load.
- **Measurement**: 3 warm-up calls discarded (librosa's first call triggers
  numba JIT); `ms_mean` and `ms_min` metrics over N iterations. The Neve side
  uses `audio_tic()`/`audio_toc()` (milliseconds since the last tic, so float
  resolution does not degrade with run time); sub-millisecond ops (loads,
  save, μ-law) are measured in batches of 10 calls inside the timing window.
  The Python side uses `time.perf_counter_ns` (ns resolution, no batching),
  so only `ms_mean` is comparable between the two sides.
- **Repetitions**: the whole benchmark runs 3 times; the tables report the median of
  the per-run means (`summary.csv` also has the min-max range). Peak RSS of each
  process is recorded by `run_with_rss.py` (`rss.csv`).
- **Threads**: **1T** column (`OMP_NUM_THREADS=1`, `torch.set_num_threads(1)`,
  pinned to one core with `taskset`) — fair comparison, since the Neve lib kernels are sequential — plus a
  **defT** column (torch/numpy default threads).
- **Correctness**: Neve writes each output as a float32 WAV; Python compares
  it against the reference outputs (metrics in `results/accuracy.csv`):
  spectrogram/mel/MFCC — SNR ≥ 110 dB; resample — SNR (dB) vs soxr/torchaudio
  (legitimately lower: different filters); μ-law — max decoded diff; time stretch —
  length, SNR and spectral convergence (all three run the same phase vocoder with
  n_fft 1024, hop 256, symmetric Hann, reflect padding; librosa is held to a looser
  SNR because it accumulates the phase unwrapped in float32); load — bit-exact
  against `soundfile`.

## Docker run — 2026-11-10

Full run in `results_current/` (`summary.csv`, `accuracy.csv`, `rss.csv`). One core, median of 3 runs, mean
milliseconds per call, 10 s mono 16 kHz unless stated. Bold = fastest.

| operation | Neve | librosa | torchaudio | Neve vs fastest Python |
|---|---:|---:|---:|---:|
| load PCM16, 1 s | **0.053** | 0.141 | 0.149 | 2.64× |
| load PCM16 | **0.316** | 0.511 | 0.512 | 1.62× |
| load PCM16, 60 s | **1.836** | 2.881 | 2.534 | 1.38× |
| load f32 | 0.238 | 0.184 | **0.155** | 0.65× |
| load f32, stereo 22 kHz | 0.916 | **0.236** | 0.255 | 0.26× |
| save PCM16 | **1.616** | 12.744 | 11.736 | 7.26×\* |
| spectrogram | **2.307** | 4.231 | 3.494 | 1.51× |
| spectrogram, 60 s | **13.220** | 24.289 | 26.121 | 1.84× |
| mel | **1.736** | 6.087 | 4.165 | 2.40× |
| mel, 60 s | **10.524** | 30.907 | 24.817 | 2.36× |
| MFCC | **1.992** | 7.517 | 4.379 | 2.20× |
| resample sinc 16→8 kHz | 0.649 | **0.569** | 1.339 | 0.88× |
| resample sinc 16→24 kHz | 1.748 | 1.627 | **1.267** | 0.72× |
| μ-law encode | **0.458** | 4.425 | 0.607 | 1.32× |
| time stretch 1.5× | **3.331** | 32.483 | 17.955 | 5.39× |

\* Save timings include the disk write and were noisy in this run: the Python per-run means ranged
5.8–13.8 ms (Neve 1.61–2.80 ms). An earlier run measured librosa 5.5 ms and torchaudio 6.2 ms, so read
this ratio as "about 4–7×".

Correctness (`accuracy.csv`): spectrogram 133–134 dB, mel 116–122 dB, MFCC 119 dB SNR against the
references; resample 16→8 kHz 44.7–45.9 dB, 16→24 kHz 40.6–41.5 dB; μ-law decoded
difference ≤ 0.038; load bit-exact against `soundfile`; time stretch 52.0 dB SNR and
0.0015 spectral convergence against torchaudio.

What is left:

- **Peak RSS of the Neve process is ~3.2 GB** (librosa 250–370 MB, torchaudio 298–358 MB). `tensor.data`
  is never freed by the runtime (see `lib/audio/IMPROVEMENT_PLAN.md`, §5.1). It also keeps the f32
  loads behind: after the kernel fix, what remains is the cost of touching fresh pages for every
  new tensor.
- **Resample** is a fixed 64-tap sinc; torchaudio's default needs 16–28 taps, and librosa's `soxr_hq` is
  a different, faster algorithm for 16→8 kHz.
- Margins below ~15% (16→8 kHz resample) can flip between runs;
  see the min-max ranges in `summary.csv`.
- Timings are on one host (i7-7700, Docker); the numbers are not portable across machines.

## Notes per operation

- **mel**: use `htk=True, norm=None` for the same filter definition.
- **resample**: reference is `soxr_hq` (librosa) and torchaudio sinc; Neve
  uses a 64-tap polyphase bandlimited sinc with a Hann window and 0.99 cutoff.
- **time_stretch**: all three run the same phase vocoder (n_fft 1024, hop 256, symmetric Hann,
  reflect padding), so waveforms are compared (SNR, spectral convergence), not just duration.
  librosa accumulates the phase unwrapped in float32 and lands ~29 dB from a float64 result,
  hence its looser tolerance.
- **mfcc**: the updated reference uses HTK mel, unnormalized filters, power dB
  and orthonormal DCT-II.
- **resample_linear**: `soxr_lq` is bandlimited, so its timing is reported as
  a separate operation instead of being compared with linear interpolation.

### Local validation of the C++ kernels

This test compiles the same C++ source in standalone mode with `g++ -O3` and
compares it with `librosa 0.11.0` using matched window, padding, mel scale and
normalization. It excludes Neve tensor and FFI overhead. The installed
torch/torchaudio binaries on this host are incompatible, so a local torchaudio
comparison was not possible. Median times over five calls with one numerical
thread, 10 s mono 16 kHz; the timings below were measured with clang++-21 inside the
benchmark image, pinned to one core (2026-11-10):

| operation | C++ kernel | librosa | numerical check |
|---|---:|---:|---|
| spectrogram | 1.67 ms | 3.83 ms | SNR 134.0 dB |
| mel | 1.55 ms | 5.71 ms | SNR 122.1 dB |
| MFCC | 1.93 ms | 7.03 ms | SNR 118.7 dB |
| resample 16k→8k | 0.47 ms | — | SNR 44.7 dB vs `soxr_hq` |
| resample 16k→24k | 1.56 ms | — | SNR 41.5 dB vs `soxr_hq` |

Times vary between runs (unpinned, the same kernels took 1.64/1.58/1.90 ms and librosa
4.40/7.23/9.19 ms). The test also covers PCM16
rounding, truncated WAV files, alias rejection, time-stretch pitch and rates, masking bounds and
invalid FFT lengths.

```bash
python3 audio_tests/benchmarks/gen_data.py
g++ -DNEVE_AUDIO_STANDALONE -O3 -mavx -fopenmp-simd -fno-math-errno -fno-trapping-math \
  -std=c++17 -fPIC -shared lib/audio/src/audio.cpp -o /tmp/libneve_audio_test.so
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1 \
  python3 audio_tests/benchmarks/validate_kernels.py

# edge cases against float64 / numpy / soundfile / librosa references
NEVE_AUDIO_TEST_SO=/tmp/libneve_audio_test.so python3 audio_tests/benchmarks/check_kernels.py
```

`validate_kernels.py` checks FFT against numpy, load against `soundfile` (bit-exact), μ-law
round trip, and the time stretch (rates 0.5–6) against a float64 phase vocoder. Edge-case and
thread-safety stress tests (ASAN/UBSAN and TSAN) are `audio_tests/stress_kernels.cpp` and
`audio_tests/stress_threads.cpp`; their build lines are in the file headers.

## Reference versions

The Docker image pins torch and torchaudio 2.5.1 for reproducibility. Current
TorchAudio documentation says the package entered maintenance and recent
`load`/`save` calls use TorchCodec. Treat I/O speed comparisons as specific
to the pinned versions: https://docs.pytorch.org/audio/stable/torchaudio.html

## Layout

```
audio_tests/benchmarks/
├── gen_data.py       # neutral test signals
├── bench_neve.nv     # Neve side (import audio)
├── bench_py.py       # librosa/torchaudio side
├── validate_kernels.py # standalone C++ accuracy and timing check
├── check_kernels.py  # edge cases vs float64/numpy/soundfile/librosa references
├── merge.py          # CSV aggregation + correctness cross-check
├── run_with_rss.py   # runs a command, records its peak RSS
├── run.sh            # orchestration (runs inside the container)
├── results_current/  # latest full run (git-ignored)
├── Dockerfile.bench  # single reproducible image
└── requirements.txt  # Python pins (torch CPU via its own index)
```
